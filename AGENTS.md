# AGENTS.md — crates/mxm-thanks-eg-engines

Parent: [`../../AGENTS.md`](../../AGENTS.md)

# Purpose

The port of Plaits' DSP to Rust: the voice, its twenty-four engines and everything they are built
from, from Emilie Gillet's MIT code, `pichenettes/eurorack` `plaits/dsp/` at commit
`f4cfa7697095a28d292bff758beb51deb49b5a86` and `pichenettes/stmlib` at
`e3bd7c9cc00e4364166f9905c0509b6ffd0535ec`. **Held bit for bit to that C++**: the frames a case
renders here equal, to the bit, the frames the C++ voice renders (`tests/digests.txt`).
Framework-free, no file IO, nothing allocated after `Voice::new`, builds for
`wasm32-unknown-unknown`.

# Local Contracts

## A file is ported from one file, as it is

- **One Rust module per C++ file**, at the same path, in snake case; types keep their C++ names,
  functions and methods become snake case, constants `K_BLOCK_SIZE` for `kBlockSize`.
- Each module opens with where it came from: `//! Ported from plaits/dsp/engine/virtual_analog_engine.{h,cc}`
  and the original's copyright line (`Copyright 2016 Emilie Gillet.`), MIT as `NOTICE.md` says.
- **No redesign while porting.** The structure, the order of statements and the names follow the
  C++, so the port reads line for line beside it. Improvements wait until every case passes.

## The bits

- **f32 arithmetic in the C++'s order.** Never `mul_add`, never reassociate, never fold a constant
  the C++ computes at run time.
- **C++'s promotions, exactly.** A literal without `f` (`0.5`, `1.0 / 3.0`) is a `double`: a
  `float` meeting one is promoted, the expression is computed in f64 and converted where the C++
  converts. Write those in f64 and cast with `as f32` at that point.
- **Float to integer as MSVC x64 does**, through `stmlib::dsp::dsp`'s helpers, never a bare `as`
  (measured with a probe built as the reference was, 2026-11-04): to `int32_t`, truncation toward
  zero, a NaN or out-of-range value giving `i32::MIN` (`cvttss2si`), where Rust's `as` saturates;
  to `uint32_t`, the low 32 bits of a 64-bit conversion (−1.5 gives 4 294 967 295, 5e9 gives
  705 032 704, a NaN 0); to a 16- or 8-bit type, the 32-bit conversion, truncated; to `size_t`
  (Plaits stores only sample counts in one), `cast_usize`, truncation, beyond 2⁶³ not measured.
- **`std::max`, `std::min` and `CONSTRAIN` as C++ evaluates them** (`cpp.rs`), never `f32::max`,
  `min` or `clamp`, which treat a NaN differently; a table indexed by an integer from a float reads
  through `cpp::at`, which never panics.
- **A table keeps its declared size**: `lut_pitch_ratio_*` are declared with 257 elements and given
  256, so the last is zero, as in C++.
- **An interpolator writes back at the end of its scope**, as the C++ destructor does (`Drop`);
  an array of them is built with `each_mut().map`, which gives the C++'s default-then-`Init` values.
- **Pointer arithmetic into a table** (`lut_fold + 1`) becomes a slice from that element; a read
  before its start returns 0 where the C++ would read the element before, so say in a comment why
  the read position can't get there.
- **The voice starts zeroed**, as the reference's `static` voice does, before `init`; a field the
  C++'s `Init` never sets keeps that zero, left unset in the port with a comment saying so.
- **A `while (size--)` loop whose body reads `size`** is a countdown in the port too, never
  `for i in 0..size`.
- **Integer arithmetic**: unsigned C++ arithmetic wraps, so use `wrapping_*`; shifts as the C++
  writes them.
- **The maths library**: at run time Plaits calls only `fabsf` and `sqrtf`, both exact in Rust
  (`f32::abs`, `f32::sqrt`). Another library function is ported only where the C++ calls it, in
  the same precision, with the case that exercises it named in a comment; the branches Plaits
  never takes (`FREQUENCY_EXACT`, `COSINE_OSCILLATOR_EXACT`: `tanf`, `sinf`, `cosf`) are compile
  errors here.
- **The one change from the C++**: `K_CORRECTED_SAMPLE_RATE` is 48 000 (the module's DAC runs at
  47 872.34 Hz; the instrument runs at 48 kHz). Nothing else differs.

## Memory: the arena the engines share

- **Each voice owns a 16 384-byte arena** (`#[repr(C, align(16))]`), handed out as stmlib's
  `BufferAllocator` hands out plaits.cc's `shared_buffer`: `free()` before each engine's `init`, so
  every engine starts at byte 0; `allocate::<T>(n)` takes `size_of::<T>() × n` bytes with no
  padding, as on x64. **An engine keeps offsets, never references**, and reads and writes its
  regions through bytemuck views of the arena passed to it. What one engine leaves, the next may
  read, as in the C++ (a six-op engine's first block after a model change does).
- A type kept in the arena is `#[repr(C)]` and `Pod`, with the C++ type's layout on x64; a C++
  pointer kept there becomes an index of the same size (8 bytes): the element offset into the table
  it points at, which is what another engine reads if it reads those bytes.
- **A type inside a type kept in the arena** (a swarm voice's oscillator) is `#[repr(C)]` and `Pod`
  in its own module, and the arena type carries a compile-time assert of its C++ size.
- **A region shared by parts that also use their own regions** (the string engine's temp buffer,
  used by each of its strings beside their delay lines) is worked on as a copy and written back,
  so the arena ends each block with the C++'s bytes.
- **An overrun the C++ makes is ported as written**: the wavetable engine allocates 64 map entries
  and `LoadUserData` writes 256, into the arena beyond them. The port writes and reads the same
  bytes, bounds-checked so it never panics.

## Randomness

- **One `Random` per voice** (stmlib's LCG, its state starting at `0x21`), passed by `&mut` to
  whatever draws from it, in the C++'s order. The C++ has one static generator for the whole
  module; a voice here draws exactly what the module's one voice draws.

## The interface

- `Patch`, `Modulations` and `Frame { out: i16, aux: i16 }` as `dsp/voice.h` has them;
  `Voice::new() -> Box<Voice>`; `Voice::render(&mut self, &Patch, &Modulations, &mut [Frame])`
  with `K_BLOCK_SIZE` (12) frames, once per block, as plaits.cc calls it.
- The frames are the module's: Plaits' output stage (×−32767, +1, clipped to 16 bits) is ported
  with the rest. Turning them into the plugin's floats is the plugin's.
- Not ported: user data, and everything of the hardware's (UI, settings, calibration, drivers).

## Clippy, and C++ pointers between objects

- **A clippy rewrite that would change the rounding or the C++'s form is declined locally**, with
  `#[allow]` and a comment saying why (`blend *= blend * (…)` rounds differently rewritten; a nibble
  swap is not a rotate). Crate-wide allows are for lints the whole port trips, each with its reason.
- **What a C++ template calls on its type parameter** becomes a trait in the template's module
  (`FractalSource`, `MetallicNoiseSource`); a functor's `operator()` becomes `call`.
- **A C++ pointer that may alias another buffer** (an FM operator reading and writing the same
  one) becomes an offset into one shared slice, read before written at each sample, as the C++.
- **A C++ subclass that only adds a setter** becomes an `impl` on that one instance of the
  generic type.
- **A C++ pointer from one object to another the engine owns** (the LPC controller's to its word
  bank) becomes a parameter of the call that uses it, so no struct borrows another.

## Realtime

No allocation, no locks and no panic on any input in `render`; overflow is handled as the C++
handles it, never by a debug panic. `#![forbid(unsafe_code)]`.

# Work Guidance

- **The engine trait**: `render(parameters, out, aux, size, &mut already_enveloped, &mut Arena,
  &mut Random)`; `init` takes the allocator, `reset` and `load_user_data` the arena. A method that
  reads no member of its own becomes an associated function while an interpolator holds fields;
  `DelayLine` takes its buffer on every call; a filter has an `_in_place` form where the C++ passes
  one buffer as input and output.
- **Port an engine with what it depends on, replace its placeholder in `voice.rs`, then add its
  index to `PORTED` in `tests/harness.rs`**: its nine cases (`eNN-*`) must then pass, and so must every shared case
  whose engines are all ported. A case that fails prints its first differing frame and block.
- The C++ is `pichenettes/eurorack` at the commit above; a local copy of it, with its checksums,
  is anywhere you fetch it to. Port from it, not from memory, and not from another port.
- Editing a file from Python: open it with `newline=''`; `pathlib.write_text` writes CRLF on
  Windows. From PowerShell, `Set-Content -Encoding utf8` writes a BOM. A commit message goes
  through `git commit -F <file>`, not a here-string on stdin.
- An engine not yet ported is a placeholder in the voice's registry: it allocates nothing and
  renders silence, so the ported engines' arena offsets are already their own.

cargo test -p mxm-thanks-eg-engines          # every case of every ported engine, bit for bit
# A mismatch: MXM_THANKS_EG_CASE=<case> runs one; MXM_THANKS_EG_RAW_DIR=<dir> writes its frames;
